<objective>
Fix feedback ID 17: in Bilderkegeln, a player who WON the Stechen (tie-break for last place) is still shown and counted as "BK Verlierer". Real case: Linden won the Stechen and was listed as loser.

Root cause (reproduced during planning against base revision a2d0c3e): the loser is derived in four independent places, and only one of them knows about the Stechen.

| Where | Rule today | Stechen-aware? | Feeds |
|-------|-----------|----------------|-------|
| server/game-types/bilderkegel.js getFinalResults | sole entry of stechenPlayers, else eligible minimum | yes (correct) | games.payer_player_id (next-game exemption), game-detail results |
| server/routes/highlights.js getBKLoserId | lowest total among non-exempt, FIRST in seat order on ties | NO | /api/highlights/current (TV ticker, tablet BK-loser symbol, idle card), /api/stats/bk-counts, /api/abende/last-summary |
| public/tv.js getBKLoserName + loserIdx in renderBilderkegelTV | lowest total, first in seat order | NO | TV end banner, red loser row |
| public/index.html renderBKSpiel (isZ, zahler) | every player with the overall minimum is tagged; box names the first of an ascending sort; ignores exemption too | NO | tablet finished view |

Reproduction (2 players tied, seat-first player throws 7 in the Stechen, the other throws 2): module payer = the other player (correct); getBKLoserId, tablet zahler and TV banner all = the seat-first player, i.e. the Stechen winner (wrong). So whenever the Stechen winner sits before the Stechen loser, every display except the exemption chain names the wrong person.

Fix strategy: one source of truth. The game module decides the loser at the moment the game ends and carries it in the state as `loserId`. The server helper and both frontends read that field instead of re-deriving from totals.

Purpose: the BK loser buys the next round and is exempt in the next BK game; naming the wrong person on the TV in front of the whole club is the visible failure.
Output: `loserId` in BK state + `getLoserId` export, delegating `getBKLoserId`, Stechen-aware TV and tablet views, an end-to-end API regression test and a frontend contract test.
</objective>

<domain_rule>
Bilderkegeln has a loser, not a winner-takes-all result. When two or more eligible players share the lowest total, they play a Stechen (one throw each per round). The LOWEST Stechen throw loses and pays; a still-tied lowest group repeats with only those players. The player exempt from losing (state.exemptPlayerId = payer of the previous BK game, "ausser Konkurrenz") never takes part in the Stechen and never loses.
</domain_rule>
