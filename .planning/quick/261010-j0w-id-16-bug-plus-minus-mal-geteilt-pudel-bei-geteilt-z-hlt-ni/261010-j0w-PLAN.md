<objective>
Fix feedback ID 16: in Plus/Minus/Mal/Geteilt a Pudel on the 5th throw (the "geteilt" throw)
must count as 9 for the game calculation. Today it counts as 1, so the operator had to enter a
literal 9 for Tino to get the right end result.

Root cause (verified in code at base revision a2d0c3e):

- `server/game-types/plus-minus-mal.js` line 5 defines `PUDEL_SUB = [0, 0, 9, 1, 1]`. `applyThrow`
  replaces a Pudel (value 0 without `meta.keinPudel`) by `PUDEL_SUB[roundIdx]` before pushing it
  into `p.wuerfe`. Every round uses the worst value for its operator (+0, +0, -9, x1) EXCEPT the
  last one: index 4 (W5, the divisor) is 1, which is the best possible divisor - a Pudel on
  "geteilt" carries no penalty at all. The club rule is divide by 9.
- The same wrong value is repeated in two operator-facing strings in `public/index.html`: the game
  description (line 327, "W5=1") and the per-round input hint (line 1457, rounds 4 AND 5 both show
  "Pudel=1").
- NOT a cause, and must stay as it is: the frontend sends the raw 0 (`doNWurf`), and
  `POST /api/games/:id/throws` inserts the raw value into `throws` BEFORE calling `applyThrow`.
  Substitution only ever lives in the in-memory / replayed `wuerfe` array. `pmCalc`
  (public/index.html) and `pmCalcTV` (public/tv.js) compute from that already-substituted array.

Purpose: correct end results without the manual-9 workaround, which pollutes the 9er statistic
(stats count `throws.value = 9`) and hides the Pudel from the Pudel statistic
(stats count `throws.value = 0` without keinPudel). Same invariant as commit 3785a21 (kleineHaus):
the DB keeps value 0, the server applies the rule.

Output: one-constant server fix, four unit regression tests, one end-to-end regression test that
pins the DB invariant, two corrected UI strings.

Scope boundaries:
- Code fix only. No DB edit, no migration: Tino's manually entered 9 is corrected later,
  separately, on the VPS.
- Results are derived by replaying stored throws, so after this fix every already finished
  Plus/Minus game that contains a real W5 Pudel (stored 0) is re-scored with divide-by-9 the next
  time stats are requested. That is the intended club rule, not a regression. Do not add any
  date/version switch to preserve the old scoring.
</objective>
